# S3 Module

This module manages the manually-created S3 buckets in Connor's AWS account. The state bucket (`connor-ruff-terraform-state`) is intentionally excluded — it's managed in `bootstrap/`.

## Buckets

| Terraform resource | Bucket name | Purpose |
|---|---|---|
| `big_money_data` | `connors-big-money-data-bucket` | Primary data bucket for the GDrive → Snowflake pipeline. Lambda writes processed files here; Snowflake reads them via the `s3-read-access-for-aws-accounts` IAM role. |
| `misc_blob` | `connors-misc-blob-for-blobs` | General-purpose blob storage. eBird data lands in `ebird/`, Zeta Ball data in `zeta_ball/`, and the GDrive pipeline also writes here. |
| `python_packages` | `connors-python-packages` | Stores Lambda deployment packages (zip files) used as Lambda code sources. |
| `zeta_ball_slopcs` | `zeta-ball-slopcs` | **Public** static website for the weekly SlopCS rankings. `index.html` is managed here (source in `site_content/zeta-ball-slopcs/`); `data/*.json` is written by Snowflake's `STG.PUBLISH_SLOPCS` via `STG.SLOPCS_SITE_STAGE`. |

## Configuration

The three private buckets share the same configuration:
- **Encryption**: AES256 server-side encryption with bucket key enabled
- **Public access**: fully blocked on all four settings
- **Versioning**: not enabled
- **Lifecycle rules**: none
- **Bucket policy**: none

`zeta-ball-slopcs` is the exception: same encryption, but public *policies* are allowed (ACLs stay blocked), a bucket policy grants public `s3:GetObject`, and static website hosting is on (`index.html`). The website URL is the `zeta_ball_slopcs_website_url` output (HTTP only; no CloudFront yet). Never put anything private in it.

## Bucket contents

This module manages buckets and their configuration, **not their contents**, with one exception: static website code. Same idea as the Lambda module deploying source from `function_code/`.

- **Managed here:** `index.html` for `zeta-ball-slopcs` (`aws_s3_object`). Source lives in `site_content/<bucket-name>/`. Edit the file and `tofu apply`; the `etag` detects the change and re-uploads.
- **Not managed here:** data written at runtime (Snowflake unloads, Lambda output, etc.), including `zeta-ball-slopcs/data/*.json`. Never add `aws_s3_object` resources for data; OpenTofu would fight the process that writes it.

## File structure

| File | Contents |
|---|---|
| `main.tf` | S3 backend, AWS provider, and shared `encryption_rule` local |
| `bucket_big_money_data.tf` | `big_money_data` bucket + encryption + public access block + imports |
| `bucket_misc_blob.tf` | `misc_blob` bucket + encryption + public access block + imports |
| `bucket_python_packages.tf` | `python_packages` bucket + encryption + public access block + imports |
| `bucket_zeta_ball_slopcs.tf` | `zeta_ball_slopcs` public website bucket + policy + website config + `index.html` object (no imports; created by OpenTofu) |
| `site_content/zeta-ball-slopcs/index.html` | The SlopCS page. Edit it and `tofu apply` to redeploy (tracked by `etag`). |
| `s3.md` | This file |
